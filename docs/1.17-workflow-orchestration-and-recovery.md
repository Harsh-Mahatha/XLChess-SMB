## Scope

Build durable job states from research through publication with retries, resumable steps, idempotency and partial channel-failure isolation.

## Done when

Failed steps resume safely without losing approval or republishing successful posts.

## From the Development Guide

### Job states

*Source: DEVELOPMENT_GUIDE.md 2.2 Post Types, Configurations & Triggers*

Pending → Researching → Generating → Awaiting Review → Approved → Scheduled → Publishing → Published

Rejected, deferred and failed states branch from the relevant stages, with controlled recovery paths.

A failure in one stage must not require the entire workflow to restart unnecessarily.

For example, a failed Instagram publication should not regenerate the approved image or republish the post to X.

### Logical architecture

*Source: DEVELOPMENT_GUIDE.md 2.1 Development Approach & Architecture*

- SMB Admin & Review Interface
- SMB Backend / Orchestrator — controls the post lifecycle and state transitions
- Configuration Manager
- Scheduler & Event Monitor
- Source Adapters
- Research & Verification
- AI Content Generator
- Image & Template Engine
- Approval Manager
- Publishing Adapters
- PostgreSQL + Asset Storage + Job Queue

The orchestrator manages state and invokes the appropriate services. It should not contain source-specific scraping logic, image rendering code or platform-specific publishing implementations.

### Job flow and capacity

*Source: DEVELOPMENT_GUIDE.md 2.1 Development Approach & Architecture*

1. XLChess queues post-production and supporting AI jobs with an ID, input data, priority, configuration version and expected output format.
2. The PC worker **polls the XLChess API over outbound HTTPS**, securely claims the next available job, and runs the necessary local model and processing steps. No public inbound port, exposed model API or permanent remote desktop connection is needed.
3. The worker sends heartbeats and progress while processing, then returns the generated content, supporting artifacts, status, errors and timing to XLChess.
4. XLChess stores the results and makes completed posts available for human approval. Publishing is performed separately by XLChess **only after approval**.

**Do not impose a fixed daily post-production limit or a guaranteed five-post minimum.** Keep the worker busy whenever eligible jobs are queued, subject to safe concurrency and resource limits. If a post takes ten hours, the PC may produce only about two per day; if it can produce more, it should. Begin with one GPU-intensive job at a time and benchmark before increasing concurrency. Prioritise time-sensitive tournament stories and expire or reconsider stale work.

### Reliability, security and acceptance

*Source: DEVELOPMENT_GUIDE.md 2.1 Development Approach & Architecture*

Use durable queue state, job leases, heartbeats, bounded retries, idempotent completion, checkpointing where practical and recovery after crashes, disconnections or reboots. A lost worker must not lose the job permanently or cause duplicate posts. Protect device credentials, use HTTPS and least-privilege permissions, keep the model server local-only, and **do not put social-media publishing credentials on the PC**.

The developer must demonstrate: **run one installer → pair the PC → receive a queued XLChess job → generate using the RTX 4070 → return a complete result → review it in XLChess → recover after an interrupted job and a PC restart**. The owner should not need further PC-side configuration. Because Windows 10 is past normal support, the developer must assess the security implications and document a supported-OS migration path without making manual OS work part of ordinary SMB administration.

Build one reusable, configuration-driven pipeline for all post types and channels. Develop it incrementally, but deliver all six components, all 18 post-type categories and all listed channel integrations as part of the completed SMB.

## From the Feature Definition

### What SMB must automate

*Source: FEATURES.md 1.1 Overview*

| Stage | What it does |
|---|---|
| Post Type Configuration & Scheduling | Determines which post is due and why |
| Data Collection & Research | Retrieves current chess information from approved sources |
| Story Selection & Fact Verification | Identifies the strongest angle and validates factual claims |
| Content & Image Production | Creates three candidate captions and finished graphics |
| Human Review & Approval | Approve, edit, reject or regenerate |
| Publishing, Monitoring & Feedback | Publishes to configured channels and records results |

Each stage must have clearly defined inputs, outputs, failure handling and status tracking. This allows the stages to be tested independently.
