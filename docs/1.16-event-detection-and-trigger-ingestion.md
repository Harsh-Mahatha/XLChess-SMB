## Scope

Consume supported provider events or rate-limited polls, normalise game-completion events and deduplicate event identities.

## Done when

A confirmed new game result produces one opportunity; replays, conflicting feeds and provider outages are handled.

## From the Development Guide

### Event detection

*Source: DEVELOPMENT_GUIDE.md 2.2 Post Types, Configurations & Triggers*

Where a provider supports event notifications, use them. Otherwise, poll approved sources at a configured interval.

Polling must respect rate limits and avoid unnecessary requests.

A newly detected event should be normalised and compared against previously processed events.

### Game-completion triggers

*Source: DEVELOPMENT_GUIDE.md 2.2 Post Types, Configurations & Triggers*

A game-completion event must contain:

- Championship and game identifiers
- Both players
- Official result
- Updated match score
- Completion timestamp
- Source reference
- Verification status

A game is considered complete only when a reliable source confirms its final result. A clock stopping, broadcast interruption or temporary feed status must not independently trigger publication.

The system must distinguish individual games from rounds, and avoid generating multiple posts for the same completed game.

Use an idempotency key such as `world-championship-2026:game-1:result` to prevent duplicates.

If a result is later corrected, update the existing content record and flag any published post for review.

### Source reliability

*Source: DEVELOPMENT_GUIDE.md 2.3 Data Sources & Content Generation*

Use the following hierarchy:

- **Official source:** Preferred for results, rankings, ratings, qualification and regulations.
- **Structured tournament feed:** Preferred for game data where authorised and reliable.
- **Established chess publication:** Used for context, analysis and news.
- **Unverified external material:** Not automatically publishable.

Conflicting information must be recorded and either resolved against an authoritative source or sent for human review.

Source failures must not silently turn into fabricated content.
