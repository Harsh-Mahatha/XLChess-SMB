## Scope

Store originals and generated assets with provenance, hashes, retention rules and deterministic crop/resize/rotation only; prevent generative alterations to real people.

## Done when

Source photo identity is preserved and verifiable by hash and permitted-transform checks.

## From the Development Guide

### Image Sourcing & Graphics

*Source: DEVELOPMENT_GUIDE.md 2.4 Image Sourcing & Graphics*

Implement verified image sourcing, licence records, immutable original photographs and deterministic graphic templates. AI may help select images or create separate decorative assets, but must never regenerate or alter an original player photograph.

### Graphics technology

*Source: DEVELOPMENT_GUIDE.md 2.4 Image Sourcing & Graphics*

Recommended initial approach:

- HTML/CSS or SVG templates for layouts.
- Sharp for image resizing, cropping and composition.
- A server-side renderer such as Playwright for producing final images from HTML templates.
- AI for choosing a visual concept, suggesting layout and generating captions.
- Deterministic rendering for the final photographs, flags, text and statistics.

This is preferable to generating the entire poster as one AI image because it gives us exact control over the photographs, factual text and output dimensions.

AI-generated backgrounds or decorative assets may be used where useful, provided they do not modify original photographs or introduce misleading visual information.

### Image integrity tests

*Source: DEVELOPMENT_GUIDE.md 2.6 Testing, Operations & Delivery*

For the World Championship reference, confirm that the original photographs are used directly.

The renderer must not replace them with AI-generated approximations.

Store the source file hash and test that any changes to the rendered photograph region are limited to the documented crop, scaling, rotation and encoding operations.

### Database design

*Source: DEVELOPMENT_GUIDE.md 2.1 Development Approach & Architecture*

The database must support the complete lifecycle, not just store published captions.

Recommended core tables:

| Table | Purpose |
|---|---|
| `post_types` | Post-type identifiers and metadata |
| `post_configs` | Versioned configurations and scheduling rules |
| `data_sources` | Approved source registry |
| `source_records` | Retrieved information and provenance |
| `research_packages` | Verified research for each posting opportunity |
| `post_opportunities` | Scheduled or triggered work |
| `post_candidates` | Three generated versions |
| `media_assets` | Original and generated images |
| `media_licenses` | Licence evidence and restrictions |
| `review_actions` | Approvals, edits, rejections and feedback |
| `publications` | Channel-specific publishing attempts and results |
| `jobs` | Background tasks, retries and failures |
| `post_metrics` | Quality and performance measurements |

Use immutable identifiers, timestamps and version numbers where appropriate.

Important relationships include:

- One posting opportunity has one or more research packages.
- One posting opportunity normally produces three candidates per generation cycle.
- One candidate can have multiple revisions.
- One approved revision can be published to multiple channels.
- Each channel publication has its own status.
- Every generated asset links back to its original source and licence record.

The developer should also implement retention and deletion policies for downloaded images, external source data and generated media.

## From the Feature Definition

### Preserve original photographs

*Source: FEATURES.md 1.2.4 Content & Graphics Production*

This is an explicit requirement based on the World Championship trial.

The original photographs must remain visually unchanged.

Permitted operations:

- Crop
- Resize
- Rotate
- Position
- Place inside a frame
- Arrange with other design elements

Not permitted:

- AI reconstruction of faces
- Retouching
- Changing facial expressions
- Changing clothing or hair
- Recolouring the photographs
- Replacing or generating portions of a photograph
- Applying generative image transformations to the player

The preferred implementation is to use the original photograph directly in a compositing system.

For example, use Sharp or another deterministic image-processing library to crop and position the original image within a template.

Do not send the entire finished graphic through a generative image model when this could redraw the people.

### Separate image selection from graphic composition

*Source: FEATURES.md 1.2.4 Content & Graphics Production*

The system needs two distinct components.

**Image selection** finds suitable photographs, verifies licences, evaluates resolution and composition, and chooses the best candidates.

**Graphic composition** combines the selected photographs with backgrounds, typography, flags, ratings, statistics and other visual elements.

This separation allows SMB to use real photographs without altering them.
