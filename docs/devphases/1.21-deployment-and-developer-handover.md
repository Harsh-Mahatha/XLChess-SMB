## From the Development Guide

### Acceptance and handover

*Source: DEVELOPMENT_GUIDE.md 2.6 Testing, Operations & Delivery*

Completion means all 18 post-type categories are configurable and operational, all listed channels are integrated, and the full research-to-publication workflow functions with mandatory human approval. The system must generate three candidate posts with source-backed claims, legally usable original photographs, correct channel graphics, duplicate-safe publishing, audit records, reliable recovery and measurable quality reporting. The developer must supply source code, database migrations, configuration schemas, setup and deployment instructions, automated tests, and administrator and integration documentation.

### What the developer must deliver

*Source: DEVELOPMENT_GUIDE.md 2.6 Testing, Operations & Delivery*

The developer is responsible for delivering a functioning, maintainable system, not just a demonstration that can generate a social media caption.

The final handover must include source code, database migrations, configuration schemas, integration documentation, setup instructions, automated tests, a deployment procedure and an administrator guide.

The developer must also document how to add a new post type, connect a new data source, create a new graphic template and add a new social media channel.

Any external service requiring payment, special permissions or a paid API tier must be identified before implementation.

### One-time, script-driven installation on the PC

*Source: DEVELOPMENT_GUIDE.md 2.1 Development Approach & Architecture*

The developer **must provide one primary PowerShell installer**, for example `setup-xlchess-worker.ps1`, so the PC owner performs only a short, one-time setup. The script must:

- Check OS, GPU and driver compatibility, available RAM, disk space and internet access; install prerequisites where practical and give clear, actionable errors otherwise.
- Install and configure the local AI runner, download the selected model, install the XLChess worker and create its working folders and logs.
- Register the machine with XLChess using a short-lived pairing code or similarly simple secure process, without manually editing credentials, environment files or application configuration.
- Configure unattended background operation and automatic startup after reboot, with restart on failure. Check that Windows sleep or hibernation will not unexpectedly stop the 24/7 worker, and offer to configure appropriate plugged-in power settings with the owner's consent. If a reboot is required during setup, support a clear resume path.
- Run an end-to-end test job, verify actual GPU acceleration, upload its output to XLChess and display a concise success or diagnostic report.
- Supply scripted worker update, repair, diagnostics and uninstall procedures.

**Docker is optional, not a requirement for the owner.** Use native Windows installation if simpler. If containers are chosen, the same installer must handle all Docker/container setup automatically. The owner must not have to manually configure Docker, Python packages, model files, ports or services. A developer-assisted remote-control session is an acceptable fallback for unusual installation problems, not the normal operating model.
