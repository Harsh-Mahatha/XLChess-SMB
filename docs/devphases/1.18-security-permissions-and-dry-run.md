## From the Development Guide

### Security and permissions

*Source: DEVELOPMENT_GUIDE.md 2.5 Review, Publishing & Integrations*

SMB will access external APIs and social media accounts, so security must be part of the initial implementation.

Requirements include secure credential storage, least-privilege access, separation of development and production credentials, audit logs and appropriate administrator permissions.

Only authorised reviewers should be able to approve content.

Only the publishing service should be able to use production social media credentials.

The system must never expose API keys, access tokens or other credentials in generated posts, logs or client-side code.

Publishing should initially operate in a sandbox or dry-run mode until the full approval and verification process has been tested.

### Reliability, security and acceptance

*Source: DEVELOPMENT_GUIDE.md 2.1 Development Approach & Architecture*

Use durable queue state, job leases, heartbeats, bounded retries, idempotent completion, checkpointing where practical and recovery after crashes, disconnections or reboots. A lost worker must not lose the job permanently or cause duplicate posts. Protect device credentials, use HTTPS and least-privilege permissions, keep the model server local-only, and **do not put social-media publishing credentials on the PC**.

The developer must demonstrate: **run one installer → pair the PC → receive a queued XLChess job → generate using the RTX 4070 → return a complete result → review it in XLChess → recover after an interrupted job and a PC restart**. The owner should not need further PC-side configuration. Because Windows 10 is past normal support, the developer must assess the security implications and document a supported-OS migration path without making manual OS work part of ordinary SMB administration.

Build one reusable, configuration-driven pipeline for all post types and channels. Develop it incrementally, but deliver all six components, all 18 post-type categories and all listed channel integrations as part of the completed SMB.

### AI safeguards

*Source: DEVELOPMENT_GUIDE.md 2.3 Data Sources & Content Generation*

Treat retrieved webpages and other external text as untrusted data.

The model must not follow instructions embedded in articles, source documents or image metadata.

Generated content must be checked against the research package. Claims without adequate evidence must be removed or flagged.

The system should also validate that the AI has not invented player ratings, tournament dates, match results, quotations or official announcements.

## From the Feature Definition

### Core principles

*Source: FEATURES.md 1.1 Overview*

The following principles must guide the development.

1. **Automation first.** The system should not depend on humans supplying topics or researching information.
2. **Configuration-driven.** Posting rules, sources, frequencies and channels must be defined through configuration rather than hardcoded for each post.
3. **Evidence-based content.** Claims about players, tournaments, rankings and results must be supported by reliable data.
4. **Human approval.** SMB must never publish unapproved content.
5. **Image integrity.** Original photographs must not be altered by AI. Cropping, resizing, rotating and positioning are permitted.
6. **Legal image use.** Every external image must have its licence verified individually.
7. **Reusable architecture.** Adding a new post type should primarily involve adding configuration, not creating an entirely new implementation.
8. **Continuous improvement.** Human corrections should be recorded and used to improve future generations.
9. **Reliability.** Scheduling, duplicate prevention, retries, publishing and failure recovery must be handled systematically.
10. **Traceability.** We must be able to identify which sources, data, images, prompts and approvals produced every published post.
