  1. Approval in force (`approval_not_in_force`)
  2. Version unchanged (`hash_mismatch`, `revision_superseded`)
  3. Required media exists & matches sha256 (`media_missing`, `media_changed`)
  4. Licence & pixel integrity (`licence_problem`, `integrity_problem`)
  5. Channel constraints & length validation (`channel_rules`, `channel_disabled`)
  6. Duplicate checks: opportunity level & caption similarity (`already_published`, `duplicate_caption`)

- Publishing Service (`apps/api/src/publishing/service.ts`): `publishPublication`, `reconcilePublication`, `publishDue`, `ensurePublications`.
- Administrator routes (`apps/api/src/http/routes/publications.ts`):
  - `GET /v1/publications`: list with filters (`status`, `channel`, `limit`, `before`) and `needsAttention` flag.
  - `GET /v1/publications/:id`: publication detail and attempt history.
  - `POST /v1/publications/:id/retry`: resets `failed` publication to `pending`, clears `attempt_count`.
  - `POST /v1/publications/:id/reconcile`: immediate reconciliation for `uncertain` status.
  - `POST /v1/publications/:id/resolve`: admin resolution (`published`, `not_published`, `abandon`).
- CLI tools: `publish:due` and `publish:one` (`apps/api/src/publishing/cli.ts`).
- Tested with 530+ unit tests and 277 integration tests including Fake X server scenarios.

## From the Development Guide

### Review, Publishing & Integrations

*Source: DEVELOPMENT_GUIDE.md 2.5 Review, Publishing & Integrations*

Implement reviewer permissions and an auditable approval workflow, then connect the same approved content package to X, Facebook, Instagram and Discord. X may be integrated first as a development step; the other channels are also required in the completed delivery. Publishing must use retries and idempotency to prevent duplicate posts.

### Publishing safeguards

*Source: DEVELOPMENT_GUIDE.md 2.5 Review, Publishing & Integrations*

Before publication, verify that:

- The post has valid approval.
- The approved version has not changed.
- The required media exists.
- Image rights and attribution requirements are satisfied.
- The post meets the channel's constraints.
- The post has not already been published.
- The scheduled time or approved immediate-publish instruction is valid.

Store the platform's returned publication identifier and URL.

A timeout must not automatically cause another publication attempt without checking whether the first request succeeded.

### Integration sequence

*Source: DEVELOPMENT_GUIDE.md 2.5 Review, Publishing & Integrations*

Implement X first as a practical development sequence.

First, make one representative post type work reliably through the complete pipeline.

Then integrate Facebook, Instagram and Discord using the same core content-generation and approval architecture; all channels must be delivered.

### Security and permissions

*Source: DEVELOPMENT_GUIDE.md 2.5 Review, Publishing & Integrations*

SMB will access external APIs and social media accounts, so security must be part of the initial implementation.

Requirements include secure credential storage, least-privilege access, separation of development and production credentials, audit logs and appropriate administrator permissions.

Only authorised reviewers should be able to approve content.

Only the publishing service should be able to use production social media credentials.

The system must never expose API keys, access tokens or other credentials in generated posts, logs or client-side code.

Publishing should initially operate in a sandbox or dry-run mode until the full approval and verification process has been tested.

## From the Feature Definition

### Publishing, Monitoring & Feedback

*Source: FEATURES.md 1.2.6 Publishing, Monitoring & Feedback*

Publishes approved content to X, Facebook, Instagram and Discord, tracks delivery, prevents duplicate publication and captures feedback so later posts improve. Each channel has its own publication status and recovery process.

### Publishing and channel integrations

*Source: FEATURES.md 1.2.6 Publishing, Monitoring & Feedback*

SMB must support:

| Channel | Content |
|---|---|
| X | Short captions, images, links and event updates |
| Facebook | Images, longer descriptions and community posts |
| Instagram | Visual-first posts and captions |
| Discord | Community announcements, images and discussions |

The developer must verify the current API permissions, account eligibility, rate limits and publishing capabilities for each platform.

Do not assume every channel supports identical post types or media requirements.

### Channel adapters

*Source: FEATURES.md 1.2.6 Publishing, Monitoring & Feedback*

Implement a shared publishing interface:

```ts
interface SocialPublisher {
  channel: string;

  validate(post: ApprovedPost): Promise<ValidationResult>;
  publish(post: ApprovedPost): Promise<PublishResult>;
  getStatus(id: string): Promise<PublicationStatus>;
}
```

Each platform adapter should handle its own authentication, media upload, formatting, rate limits and error responses.
