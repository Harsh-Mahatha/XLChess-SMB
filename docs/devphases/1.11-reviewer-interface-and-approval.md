## Scope

Show three complete candidates with graphics, source links, image rights and channel previews; allow approve, edit, regenerate, reject and defer with version-aware permissions.

## Done when

Only an authorised approval of the exact final revision can unlock publishing; every review action is recorded.

## Notes

- The review screens live in the XLChess web application; SMB provides the API and approval logic behind them.

## From the Development Guide

### Review, Publishing & Integrations

*Source: DEVELOPMENT_GUIDE.md 2.5 Review, Publishing & Integrations*

Implement reviewer permissions and an auditable approval workflow, then connect the same approved content package to X, Facebook, Instagram and Discord. X may be integrated first as a development step; the other channels are also required in the completed delivery. Publishing must use retries and idempotency to prevent duplicate posts.

### Security and permissions

*Source: DEVELOPMENT_GUIDE.md 2.5 Review, Publishing & Integrations*

SMB will access external APIs and social media accounts, so security must be part of the initial implementation.

Requirements include secure credential storage, least-privilege access, separation of development and production credentials, audit logs and appropriate administrator permissions.

Only authorised reviewers should be able to approve content.

Only the publishing service should be able to use production social media credentials.

The system must never expose API keys, access tokens or other credentials in generated posts, logs or client-side code.

Publishing should initially operate in a sandbox or dry-run mode until the full approval and verification process has been tested.

### Publishing safeguards

*Source: DEVELOPMENT_GUIDE.md 2.5 Review, Publishing & Integrations*

Before publication, verify that:

- The post has valid approval.
- The approved version has not changed.
- The required media exists.
- Image rights and attribution requirements are satisfied.
- The post meets the channel's constraints.
- The post has not already been published.
- The scheduled time or approved immediate-publish instruction is valid.

Store the platform's returned publication identifier and URL.

A timeout must not automatically cause another publication attempt without checking whether the first request succeeded.

### Management through XLChess

*Source: DEVELOPMENT_GUIDE.md 2.1 Development Approach & Architecture*

After initial pairing, routine administration must be available through the XLChess web application: worker online/offline state, current job, queue and priorities, completed and failed jobs, processing time, health and GPU usage, logs, pause/resume, retries, concurrency and resource limits, model selection/downloads, prompts, configuration versions and controlled worker updates. Configuration changes must reach the PC without requiring the owner to log in and edit files.

## From the Feature Definition

### Human Review & Approval

*Source: FEATURES.md 1.2.5 Human Review & Approval*

Provides the human reviewer with complete posts, source evidence, images and licence information. The reviewer can approve, edit, reject, defer or regenerate content. No unapproved post may be published.

### Human review and approval

*Source: FEATURES.md 1.2.5 Human Review & Approval*

SMB requires a review interface.

A reviewer should receive a complete package, not an unfinished idea requiring further research.

Each package must include the three candidate versions, their graphics, captions, intended channels, source references and licence information.

### Review actions

*Source: FEATURES.md 1.2.5 Human Review & Approval*

| Action | Behaviour |
|---|---|
| Approve | Select a candidate for publication |
| Edit | Modify text, layout or selected imagery |
| Regenerate | Produce new candidates using feedback |
| Reject | Reject the posting opportunity |
| Defer | Hold publication until later |
| Request research | Return the post for additional fact verification |

Approval must apply to a specific version of the content.

If the caption or image changes after approval, the approval must be invalidated unless the change is an explicitly permitted non-content transformation.

### Reviewer interface

*Source: FEATURES.md 1.2.5 Human Review & Approval*

The review screen should provide:

- A queue of posts awaiting review.
- Previews for X, Facebook, Instagram and Discord.
- Three candidate versions displayed for comparison.
- Source links and evidence supporting the claims.
- Image licence and attribution information.
- Editing controls.
- Regeneration instructions.
- Approve, reject and defer actions.
- Scheduled publication time.
- Publication history.
