## Scope

After X is reliable, implement additional channel adapters with channel-specific media, formatting, permissions, errors and publication records.

## Done when

Each enabled channel publishes only its approved revision, and a failure in one channel does not republish another.

## From the Development Guide

### Integration sequence

*Source: DEVELOPMENT_GUIDE.md 2.5 Review, Publishing & Integrations*

Implement X first as a practical development sequence.

First, make one representative post type work reliably through the complete pipeline.

Then integrate Facebook, Instagram and Discord using the same core content-generation and approval architecture; all channels must be delivered.

### Publishing safeguards

*Source: DEVELOPMENT_GUIDE.md 2.5 Review, Publishing & Integrations*

Before publication, verify that:

- The post has valid approval.
- The approved version has not changed.
- The required media exists.
- Image rights and attribution requirements are satisfied.
- The post meets the channel's constraints.
- The post has not already been published.
- The scheduled time or approved immediate-publish instruction is valid.

Store the platform's returned publication identifier and URL.

A timeout must not automatically cause another publication attempt without checking whether the first request succeeded.

### Job states

*Source: DEVELOPMENT_GUIDE.md 2.2 Post Types, Configurations & Triggers*

Pending → Researching → Generating → Awaiting Review → Approved → Scheduled → Publishing → Published

Rejected, deferred and failed states branch from the relevant stages, with controlled recovery paths.

A failure in one stage must not require the entire workflow to restart unnecessarily.

For example, a failed Instagram publication should not regenerate the approved image or republish the post to X.

## From the Feature Definition

### Publishing and channel integrations

*Source: FEATURES.md 1.2.6 Publishing, Monitoring & Feedback*

SMB must support:

| Channel | Content |
|---|---|
| X | Short captions, images, links and event updates |
| Facebook | Images, longer descriptions and community posts |
| Instagram | Visual-first posts and captions |
| Discord | Community announcements, images and discussions |

The developer must verify the current API permissions, account eligibility, rate limits and publishing capabilities for each platform.

Do not assume every channel supports identical post types or media requirements.

### Channel adapters

*Source: FEATURES.md 1.2.6 Publishing, Monitoring & Feedback*

Implement a shared publishing interface:

```ts
interface SocialPublisher {
  channel: string;

  validate(post: ApprovedPost): Promise<ValidationResult>;
  publish(post: ApprovedPost): Promise<PublishResult>;
  getStatus(id: string): Promise<PublicationStatus>;
}
```

Each platform adapter should handle its own authentication, media upload, formatting, rate limits and error responses.
