## Scope

Create a source registry with provider capabilities, reliability and access/licensing rules; implement initial authorised adapters using a shared interface, caching, limits and errors.

## Done when

At least one approved real chess data source is integrated and normalised; unsupported provider capabilities fail explicitly.

## From the Development Guide

### Data Sources & Content Generation

*Source: DEVELOPMENT_GUIDE.md 2.3 Data Sources & Content Generation*

Build adapters for approved data sources, a verifiable research package, a structured story-selection process and an AI-assisted generation service. The AI integration must be provider-independent: an open-weight model can run locally or through a compatible API, with the option to change providers without changing the SMB pipeline. Model weights may be free, but computing resources are not. Factual calculations, source validation, scheduling and publishing state remain deterministic software responsibilities.

### Source adapters

*Source: DEVELOPMENT_GUIDE.md 2.3 Data Sources & Content Generation*

Implement a separate adapter for each source, using a shared interface.

For example:

```ts
interface ChessDataSource {
  id: string;

  fetchEvents(query: EventQuery): Promise<ChessEvent[]>;
  fetchPlayers(query: PlayerQuery): Promise<ChessPlayer[]>;
  fetchGames(query: GameQuery): Promise<ChessGame[]>;
  fetchNews(query: NewsQuery): Promise<ChessNews[]>;
}
```

These methods illustrate the common architecture; an adapter should only implement capabilities its provider actually supports.

Each adapter is responsible for authentication, fetching, rate limits, caching, normalisation and error handling.

The rest of SMB should work with common data structures rather than needing to understand the individual providers.

### Source reliability

*Source: DEVELOPMENT_GUIDE.md 2.3 Data Sources & Content Generation*

Use the following hierarchy:

- **Official source:** Preferred for results, rankings, ratings, qualification and regulations.
- **Structured tournament feed:** Preferred for game data where authorised and reliable.
- **Established chess publication:** Used for context, analysis and news.
- **Unverified external material:** Not automatically publishable.

Conflicting information must be recorded and either resolved against an authoritative source or sent for human review.

Source failures must not silently turn into fabricated content.

## From the Feature Definition

### Data Collection & Research

*Source: FEATURES.md 1.2.2 Data Collection & Research*

Collects reliable chess information from approved sources and prepares evidence that the rest of SMB can use. Every claim must be traceable to its source; conflicting or unavailable information must not be invented.

### Data sources and research

*Source: FEATURES.md 1.2.2 Data Collection & Research*

SMB must use a defined registry of approved chess information sources. The developer must not build a system that performs unrestricted internet searches and automatically treats the results as factual.

Every source should have a known purpose, reliability level, access method and usage policy.
