## From the Development Guide

### Data Sources & Content Generation

*Source: DEVELOPMENT_GUIDE.md 2.3 Data Sources & Content Generation*

Build adapters for approved data sources, a verifiable research package, a structured story-selection process and an AI-assisted generation service. The AI integration must be provider-independent: an open-weight model can run locally or through a compatible API, with the option to change providers without changing the SMB pipeline. Model weights may be free, but computing resources are not. Factual calculations, source validation, scheduling and publishing state remain deterministic software responsibilities.

### Content quality requirements

*Source: DEVELOPMENT_GUIDE.md 2.3 Data Sources & Content Generation*

The generated content must:

- Be factually accurate and current.
- Avoid misleading headlines.
- Use the correct player names, titles and countries.
- Distinguish classical, rapid and blitz ratings.
- Clearly distinguish predictions from confirmed facts.
- Avoid repeating recently published content.
- Respect each channel's formatting and length requirements.
- Use natural, engaging language.
- Avoid unnecessary promotional language.
- Avoid plagiarism or reproducing substantial copyrighted text.

The content generator should return structured data rather than only a block of prose.

Example:

```json
{
  "postType": "1.1",
  "angle": "Championship rating comparison",
  "candidates": [
    {
      "version": "A",
      "headline": "Championship Preview",
      "caption": "Example caption...",
      "claims": ["claim-001", "claim-002"],
      "visualTemplate": "player-versus"
    }
  ]
}
```

This is an illustrative partial response; the production schema must also represent all three versions, source references, media requirements and validation results.

### AI implementation

*Source: DEVELOPMENT_GUIDE.md 2.3 Data Sources & Content Generation*

AI should be used for tasks requiring language understanding, interpretation, editorial judgment and creative generation.

It should not replace deterministic code for calculations, licence validation, scheduling or publication state management.

### Recommended AI tasks

*Source: DEVELOPMENT_GUIDE.md 2.3 Data Sources & Content Generation*

- Interpreting collected research.
- Identifying potential stories.
- Ranking story angles.
- Creating headlines.
- Writing captions.
- Producing three candidate versions.
- Suggesting appropriate visual templates.
- Reviewing drafts against the research package.
- Analysing human feedback.

### Prompt architecture

*Source: DEVELOPMENT_GUIDE.md 2.3 Data Sources & Content Generation*

Do not build one enormous prompt that attempts to perform the entire workflow.

Use separate prompts or model operations for:

1. Research interpretation.
2. Story selection.
3. Candidate generation.
4. Editorial verification.
5. Visual planning.
6. Revision based on reviewer feedback.

Each stage must use structured input and output schemas.

Prompts should be version-controlled, and each generated candidate should record the model, prompt version and relevant generation settings.

### AI safeguards

*Source: DEVELOPMENT_GUIDE.md 2.3 Data Sources & Content Generation*

Treat retrieved webpages and other external text as untrusted data.

The model must not follow instructions embedded in articles, source documents or image metadata.

Generated content must be checked against the research package. Claims without adequate evidence must be removed or flagged.

The system should also validate that the AI has not invented player ratings, tournament dates, match results, quotations or official announcements.

### Available worker hardware

*Source: DEVELOPMENT_GUIDE.md 2.1 Development Approach & Architecture*

This home PC is a Windows 10 Home 64-bit machine with an Intel Core i7-8700K (6 cores / 12 threads), NVIDIA RTX 4070 (12 GB VRAM), 64 GB RAM, a 500 GB SSD and additional storage. Design for this machine, benchmark actual GPU memory and processing time, and make it possible to add or replace workers later. A quantised Qwen3 8B model through Ollama (or a comparably suitable local model runner) is a starting candidate, **not a mandatory model choice**. Prefer an open-weight model that can run without a paid per-request API; document model licence and hardware costs.

## From the Feature Definition

### Content & Graphics Production

*Source: FEATURES.md 1.2.4 Content & Graphics Production*

Produces three meaningfully different, finished candidate posts, including headlines, captions and graphics appropriate for the selected channels. Photographs must remain original: only cropping, resizing, rotating and positioning are permitted.

### Three candidate versions

*Source: FEATURES.md 1.2.4 Content & Graphics Production*

For every posting opportunity, generate three versions.

These should be meaningfully different, not simply three minor wording variations.

| Candidate | Approach |
|---|---|
| A | Factual and informative |
| B | Strong headline or compelling narrative |
| C | Engagement-focused, such as a question or comparison |

All three must be factually correct and grounded in the same verified research.

Each candidate should include its headline, caption, supporting facts, visual instructions and channel-specific variants.
