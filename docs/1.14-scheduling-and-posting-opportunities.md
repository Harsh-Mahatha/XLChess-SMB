## Scope

Implement timezone-aware fixed, event-driven and manual triggers that create a common opportunity record; handle DST, disabled schedules, suspension and missed executions.

## Done when

Every due posting opportunity is created once, with the triggering reason and next-run state recorded.

---

## From the Development Guide

### Scheduling and event processing

*Source: DEVELOPMENT_GUIDE.md 2.2 Post Types, Configurations & Triggers*

SMB must support three trigger types.

| Trigger | Example |
|---|---|
| Fixed schedule | Every Friday at 09:00 UTC |
| Event-driven | A World Championship game finishes |
| Manual | An administrator requests an additional post |

All triggers should create a common `PostOpportunity` record. The rest of the pipeline should not need to know whether the opportunity came from a scheduler, an event or a manual request.

### Scheduler requirements

*Source: DEVELOPMENT_GUIDE.md 2.2 Post Types, Configurations & Triggers*

- Store schedules with explicit timezone information.
- Calculate the next execution time correctly.
- Handle daylight saving where relevant.
- Avoid duplicate executions.
- Recover from missed executions after downtime.
- Respect enabled/disabled status.
- Support temporary suspension of recurring schedules.
- Log when and why every job was created.
