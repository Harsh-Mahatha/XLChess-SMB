## Scope

## From the Development Guide

### Post Types, Configurations & Triggers

*Source: DEVELOPMENT_GUIDE.md 2.2 Post Types, Configurations & Triggers*

Implement versioned post-type configuration, scheduling and event detection so the same system can handle all 18 categories. The World Championship is the reference example for a post type whose behaviour changes automatically before, during and after an event.

### Configuration requirements

*Source: DEVELOPMENT_GUIDE.md 2.2 Post Types, Configurations & Triggers*

Each subtype requires a configuration containing:

| Field | Description |
|---|---|
| `id` | Stable identifier, e.g. `1.1` |
| `name` | Human-readable name |
| `enabled` | Whether the subtype is active |
| `sources` | Approved data source identifiers |
| `imageSources` | Approved image source identifiers |
| `channels` | X, Facebook, Instagram, Discord |
| `schedule` | Fixed time, frequency or event trigger |
| `timezone` | Timezone for scheduled execution |
| `phases` | Optional lifecycle-specific behaviour |
| `contentRules` | Required facts, tone, structure and restrictions |
| `imageRules` | Image selection and composition requirements |
| `approvalRequired` | Whether human approval is mandatory |
| `priority` | Importance relative to other posts |
| `deduplication` | Rules preventing repeated content |
| `retryPolicy` | Failure and retry behaviour |

Configurations should be stored as version-controlled JSON or equivalent typed configuration, with schema validation.

A database may maintain runtime overrides, but the underlying configuration must remain understandable, testable and auditable.

### Worked example — World Championship (PT 1.1)

*Source: DEVELOPMENT_GUIDE.md 2.2 Post Types, Configurations & Triggers*

The World Championship is the reference implementation. It demonstrates why SMB requires more than a simple posting calendar.

This subtype remains active throughout successive World Championship cycles, changing its behaviour automatically according to the tournament phase.

### Configuration

*Source: DEVELOPMENT_GUIDE.md 2.2 Post Types, Configurations & Triggers*

| Property | Value |
|---|---|
| Post type | 1.1 — World Championship |
| Data sources | D1, D2, D3, D4, D5 |
| Image sources | I1, I2, I3, I4 |
| Channels | X, Facebook, Instagram, Discord |
| Normal schedule | Friday, 09:00 UTC |
| Tournament schedule | After each completed game |
| Candidate versions | 3 |
| Approval | Mandatory |

## From the Feature Definition

### Post Type Configuration & Scheduling

*Source: FEATURES.md 1.2.1 Post Type Configuration & Scheduling*

Defines which types of posts SMB produces, when each post is due, and how event-driven and scheduled content is selected. The 18 post-type categories and their subtypes are supported by reusable configuration, rather than separate hard-coded pipelines.

The hierarchy is a content taxonomy, not 18 separate applications. The developer should build a single reusable processing pipeline.

Scheduling supports recurring schedules, tournament milestones, completed rounds or games, rankings updates and authorised manual requests. The configuration controls post frequency, priorities, eligible channels and duplicate prevention.
